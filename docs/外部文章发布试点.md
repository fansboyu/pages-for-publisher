# 外部文章发布：本地试点

当前是 v1.3.9 之后的本地增量，未发布版本、未部署生产。

## 已实现

- 管理员和代理商可在“外部文章发布”入口选择权限范围内网站的已有文章。
- 模拟网站媒体分页展示，每页12条，支持行业、地区、名称筛选，服务端缓存5分钟；跨页最多选择10个渠道。
- 报价冻结标题、正文、渠道和价格参考，2分钟有效；源文章修改或删除不改变快照。
- 一个批次对应一张金额账单，每个渠道对应独立子订单。重复提交使用请求编号返回原批次。
- 独立外发Worker使用PostgreSQL持久任务表及租约，与官网构建Worker分开运行；无需增加Redis卷。
- 模拟成功、拒稿、部分成功、提交超时、进程中断待核查。超时不自动重复投稿，管理员可在账单中核查释放。
- 目前所有批次金额为0；真实收费、真实投稿均被服务端阻断，不代表非零金额结算已通过验收。

## 本地运行

`.env.local`设置`EXTERNAL_PUBLISH_MODE=mock`，密钥放`XIAOQINGWA_API_KEY`，该文件须保持Git忽略。

运行
pm run dev`，会同时启动API、官网Worker、外发Worker及本地Agent。控制台入口：<http://127.0.0.1:4418/>。

生产Compose仅预留`external` profile，尚未启用。未来经正式验收后使用`docker compose --profile external up -d external-worker`启动独立容器。

迁移013包含缓存、报价、批次和子订单；迁移014使源文章删除后仍保留冻结稿件。升级须先迁移。

## 真实API只读验证

2026-11-07已打开公开Apifox文档，不需要登录：

- [媒体资源列表](https://s.apifox.cn/ecc95f5a-3182-406a-aeb5-8930e3a06e65/404388141e0)：POST `/api/media/media_list`，multipart/form-data：api_key、page、page_size。响应code=1，data为资源数组，包含resource_id、title、remarks、price等。
- [投稿媒体](https://s.apifox.cn/ecc95f5a-3182-406a-aeb5-8930e3a06e65/404721133e0)：POST `/api/media/send`，api_key、resource_id、title、HTML content；remark、third_id可选。成功返回order_nid。
- [订单详情](https://s.apifox.cn/ecc95f5a-3182-406a-aeb5-8930e3a06e65/404831215e0)：POST `/api/media/order_info`，api_key、order_nids。状态0待安排、1已安排、2已发布、4已退稿、9售后中。order_url为结果链接。响应schema与示例的data数组/对象存在差异，适配时须兼容并验证。

已使用本地配置密钥，在用户提供的`https://api.yuanmenggou.com`域名调用媒体资源列表第一页、每页2条，返回HTTP200、code=1、2条真实资源。未调用投稿接口。

可重复执行
ode scripts/external-readonly.mjs`。该命令只输出状态与数量，不打印密钥、不写真实订单。界面当前仍是模拟渠道，不能将只读连通视为真实投稿验收。

## 下一步真实发布接入

需要确定测试文章、具体媒体和总金额上限，再接通真实报价预占、资源价格复核、HTML图片公网可读检查、真实订单轮询、退款及人工核账。`third_id`只是业务标识，文档没有承诺幂等，提交超时必须进入待核查，不能自动重发。

资源列表文档暂未列出总条数及服务端筛选参数。正式目录需核实供应商分页结束规则和分类字段，不应假装支持全库筛选；可按页同步到本地索引后查询。不得一次性向浏览器返回全部资源。
