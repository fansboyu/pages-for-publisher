# GEO单次查询闭环（本地增量）

## 已实现

复用现有external-worker进程/容器。每轮分别调度一次媒体订单和一次GEO任务，各自的异常互不阻断。GEO使用PostgreSQL持久任务表、SKIP LOCKED和120秒租约，不新增Redis队列或容器。

流程：选择网站和模式 → 一个问题/多个平台 → 获取2分钟报价 → 确认总金额 → 同事务预占金额、保存每平台账单及任务 → Worker提交 → 保存request_id → 轮询进度 → 结果结算 → 独立下载并归档截图 → 更新记录和报表。

默认GEO_QUERY_MODE=demo，演示也经过Worker，金额为0且不调用供应商。正式与演示的记录、报表完全隔离。旧演示记录保留。

## 正式模式配置

1. API与external-worker均配置GEO_QUERY_MODE=live，使用已有XIAOQINGWA_API_KEY，不在浏览器保存Key。
2. 直营管理员进入AI数据中心 → 发起查询 → GEO单价，填写每问题每平台的金额并启用。初始价格0、开关关闭，不猜测销售单价。
3. 用户选择正式模式，获取报价后确认金额再提交。Kimi未通过创建任务契约验收，正式查询不开放。
4. 截图复用STORAGE_DRIVER：生产设置oss时使用现有OSS_MEDIA_BUCKET、OSS_REGION、RAM凭据和MEDIA_PUBLIC_BASE_URL；本地使用local。上传失败不重新查询或收费。
5. 生产须先运行迁移016，再启动API和external-worker。现有Compose可通过external profile运行同一个Worker，无新增容器。

## 金额和异常规则

一个平台对应一张金额账单。多平台报价和提交整体事务完成，支持请求编号幂等、报价有效期、价格版本、余额、客户月预算和待处理数量控制。命中或未命中都属于完成查询，正常扣款。供应商返回status=3（文档明确失败已退款）时释放预占。

提交超时、响应缺少编号或执行器失联进入待核查，禁止自动重复提交。管理员可沿用余额与账单中的核查释放功能；释放前须核对供应商，不能把网络超时当作未收费。已提交任务轮询可重试，超过24小时或持续异常进入待核查。人工释放后任务停止自动执行并等待核查。

截图归档与查询结算分开。查询结果先持久化并结算，截图自动重试最多5次；之后显示重试归档按钮。该按钮只重试下载上传，不会创建新查询。供应商没有返回截图时明确标注。截图仅允许HTTPS、拒绝内网地址与重定向、固定DNS解析地址、限制大小及像素后转为WebP，使用现有存储接口。

## 接口与文件

- 迁移016_geo_live_workflow.sql：价格配置、报价、任务租约/阶段/归档字段。
- pilot/geo-workflow.mjs：报价、预占、Worker任务与结算。
- pilot/geo-provider.mjs：POST /api/geo/add_shoulu与/api/geo/check_task，截图受控下载。
- GET /api/geo-query?site=...&mode=demo|live&page=1：记录与报表。
- POST /api/geo-query：action=prices、quote、submit、retry-archive。
- public/geo-query-ui.js：模式选择、单价配置、获取报价/确认提交、记录状态及截图链接，处理中每10秒刷新。

## 验证与边界

仓库默认正式计费关闭；本次本地已按用户要求设置0.20元并启用，没有执行真实付费GEO请求或云端OSS联合验收。真实供应商每个平台的稳定性、分享链接与截图可用性仍需在明确的费用范围内验收。UI中的演示数据不得当作真实品牌排名报告。
