# v1.2：每台服务器一个Agent和专用Caddy

版本：1.2.0；Git标签：v1.2。

## 边界与职责

总控：frontend、API、Worker、PostgreSQL、Redis五个常驻容器，migrate为一次性任务。入口HTTPS由总控主机Caddy提供。客户侧Caddy是另一套独立实例，不能让客户Agent接管总控入口Caddy，否则整份配置加载会覆盖后台入口。

客户服务器：一个Agent服务、一个专用Caddy服务。不同网站共用80/443，通过域名区分，不需要每站一个端口或容器。数据库中多个sites可绑定同一个server_id。一个客户也可以拥有多个网站。

Agent是服务器身份，不是单个网站账号。凭据只保存于受保护的agent.json；Caddy管理接口2019和本机健康检查4322只监听回环地址。Redis、数据库不开放给客户服务器。

## 接入步骤

1. 总控管理员注册一次服务器，取得独立Agent凭据。
2. 客户服务器安装Node.js24、应用依赖和官方Caddy，准备site-agent用户、caddy组及数据目录。使用deploy/site-agent.service示例；服务账号需能写入数据目录，Caddy账号需能读取网站文件。
3. 配置deploy/agent.example.json中的control（总控HTTPS地址）和token；root固定为独立的数据目录。保留mode=production、caddyAdmin=http://127.0.0.1:2019。不要使用本地演示模式上线。
4. 以deploy/Caddyfile进行首次引导，再以caddy run --resume恢复自动保存配置；证书数据、自动保存配置应属于Caddy服务账号并持久保存。Caddy要先启动，Agent后启动。
5. 总控给各网站绑定域名、模板和同一服务器。在DNS服务商处把这些域名分别解析到客户服务器公网IP。错误的AAAA记录也应修正。
6. 安全组和防火墙允许80/443；逐站发布，查看部署任务、Agent心跳。
7. 从外部网络检查每个域名的HTTPS、证书、首页、文章和资源。当前本机HTTP检查成功不等于公网证书已验收。

当前注册服务器只填写名称，没有独立公网IP字段；IP由DNS与运维管理，不作为Agent认证。创建网站、绑定服务器和模板目前是管理员权限，尚未开放代理商自助开户或服务器授权。一个站点目前一个域名，www/裸域名别名还需后续扩展。

## 多站点更新原则

```text
Agent本地确认清单
  网站甲 → 版本甲 → 网站甲独立目录
  网站乙 → 版本乙 → 网站乙独立目录
                 ↓ 更新网站甲时保留网站乙
生成完整Caddy配置 → /load加载 → 本机校验 → 保存清单 → 回报总控
```

文件路径为root/sites/<site-id>/releases/<release-id>。新增网站保留旧网站路由；回滚只替换目标网站版本。未知域名返回404，不作为默认客户站点处理。单台服务器部署任务顺序领取，防止多个任务并发覆盖配置。

不要手动修改Agent管理的Caddy来添加其他应用，也不要删除agent-state.json。它记录完整站点路由，启动时Agent以这份已确认清单恢复。备份该文件、站点目录、Caddy证书和配置；恢复操作需要先校对它们的一致性。

v1.2对热加载后首页检查增加短暂重试并使用新连接，避免旧keep-alive连接关闭导致误报。配置无效时Caddy保留旧配置；本机验证失败时Agent尝试恢复此前整份配置。回滚不是高可用保障，磁盘故障/Caddy停机仍会影响同机全部网站。

发布前同时补上账号范围校验：缺少agency_id的代理商账号不能登录，其已有会话不能读取状态或访问网站，避免NULL过滤退化为全平台数据。数据库角色/归属的组合约束与完整权限审计仍需后续完善，不表示实现了数据库RLS。

## 验证命令

```text
npm ci
npm run infra
npm test
npm run test:multi-site
docker compose -f compose.frontend-local.yml build
npm run test:frontend
```

需Docker及本机官方Caddy。Windows放tools/caddy.exe；Linux设置CADDY_BIN为已安装二进制路径。Node版本至少24。运行时数据与凭据保存在被Git忽略的storage中，不上传业务数据库、Agent凭据、证书或云密钥。

测试覆盖：实际PostgreSQL/Redis、一个Agent和Caddy同时部署两个网站、单站更新/回滚、Agent恢复全部站点、总控停机不影响两个网站、队列恢复、富文本、归档校验、GEO；域名专项使用生产Host路由在回环HTTP随机端口验证，未开放公网80/443、未申请公网证书。

实际OSS、云服务器、DNS、证书签发/续期需另行验收；没有实现域名别名、网站迁移后旧路由清理、代理商服务器授权和高可用。生产前还应处理账号归属约束、备份、监控、容量与权限审计。

## 版本与历史

本文记录v1.2的多站点设计与验收范围。当前代码已升级到v1.3.1，入口与结构见[当前架构](architecture.md)。历史仓库分支发布实现已经移除；SQLite历史数据仍可通过只读工具迁移。试点代码版本不表示已完成真实云端生产验收。
