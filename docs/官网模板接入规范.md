# 静态官网模板接入规范（standard-static-v1）

本规范用于把新的静态官网接入“多租户静态发布中心”。遵守本规范的官网不需要新增 Worker 代码：创建站点、配置仓库和 API Key 后，即可发布文章。

## 1. 发布分支约定

每个官网使用同一个 GitHub 仓库，建议保持两个分支：

```text
master   官网模板源代码；人工改版、调整视觉和新增模板文件在此分支完成。
publish  Worker 生成的正式静态产物；Cloudflare Pages 应监听此分支。
```

不要直接在 `publish` 分支修改页面。下一次文章发布会以 `master` 模板重新生成全部静态文件。

## 2. 最小目录结构

模板根目录由发布中心的 `templateRoot` 配置决定。常见项目使用根目录 `.`：

```text
.
├─ index.html
├─ news/
│  └─ index.html
├─ assets/
├─ templates/
│  ├─ article.html
│  └─ article-card.html       # 可选，但建议提供
├─ publisher.config.json
├─ robots.txt
└─ sitemap.xml
```

如果模板被放进仓库的 `website-template/` 目录，则后台填写：

```text
templateRoot = website-template
```

目录内的文件结构仍按本规范组织。

## 3. publisher.config.json

Worker 会优先读取模板根目录的 `publisher.config.json`。建议使用以下标准配置：

```json
{
  "version": 1,
  "homePage": "index.html",
  "newsListPage": "news/index.html",
  "articleTemplate": "templates/article.html",
  "articleCardTemplate": "templates/article-card.html",
  "articleOutput": "news/{{slug}}/index.html",
  "assetsDirectory": "assets",
  "articleCardsPlaceholder": "{{article_cards}}"
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `homePage` | 首页文件，相对模板根目录。 |
| `newsListPage` | 资讯列表页文件。 |
| `articleTemplate` | 文章详情页模板。 |
| `articleCardTemplate` | 文章卡片模板；留空时使用通用卡片 HTML。 |
| `articleOutput` | 单篇文章输出路径，必须包含 `{{slug}}`。 |
| `assetsDirectory` | 静态资源目录，Worker 用它计算文章页的相对资源路径。 |
| `articleCardsPlaceholder` | 首页和列表页中用于替换文章卡片的占位符。 |

兼容说明：未配置 `publisher.config.json` 的旧站点会采用上述默认路径，并兼容 `<!-- ARTICLE_CARDS_START -->` 与 `<!-- ARTICLE_CARDS_END -->` 标记；新网站应统一使用本配置文件和 `{{article_cards}}`。

## 4. 首页与资讯列表页

首页与 `news/index.html` 均必须保留占位符：

```html
<div class="article-grid">
  {{article_cards}}
</div>
```

每次发布时，Worker 会将该占位符替换成当前站点所有已发布文章的卡片。不要把占位符放进 JavaScript 字符串、HTML 属性或注释中。

## 5. 文章卡片模板（可选）

`templates/article-card.html` 只包含一张卡片的 HTML。例如：

```html
<article class="insight-card">
  <time datetime="{{published_at_iso}}">{{published_at}}</time>
  <p class="category">{{category_name}}</p>
  <h3><a href="{{article_url}}">{{title}}</a></h3>
  <p>{{summary}}</p>
  <a href="{{article_url}}">阅读文章 <span>→</span></a>
</article>
```

卡片可使用的变量：`article_id`、`article_url`、`title`、`summary`、`category_name`、`published_at`、`published_at_iso`、`cover_image_url`。

## 6. 文章详情页模板

`templates/article.html` 负责网站视觉外壳：页头、导航、文章正文样式、相关推荐、页脚与 SEO。正文只在 `{{content_html}}` 所在位置插入。

```html
<main>
  <a href="{{home_url}}">首页</a>
  <a href="{{news_index_url}}">行业资讯</a>
  <h1>{{title}}</h1>
  <p>{{summary}}</p>
  {{cover_image_block}}
  <article class="article-content">{{content_html}}</article>
  <section class="related">{{related_articles}}</section>
</main>
```

建议在模板中加入以下约束，防止编辑器或 Webhook 文章中的图片突破正文宽度：

```css
.article-content img,
.article-content video,
.article-content iframe {
  display: block;
  max-width: 100% !important;
  height: auto !important;
  margin: 24px auto;
}
```

详情页可使用变量：

```text
article_id, title, title_json, summary, summary_json, content_html,
category_name, published_at, published_at_iso, updated_at_iso,
seo_title, seo_description, seo_keywords, canonical_url,
cover_image_url, cover_image_block, tag_links, related_articles,
home_url, news_index_url, asset_prefix
```

其中 `content_html`、`cover_image_block`、`tag_links` 和 `related_articles` 是安全 HTML 片段，不能再次转义；其余文本变量应直接放入文本节点或属性中。

## 7. 发布中心站点配置

管理员新增站点时填写：

```text
官网域名：客户正式域名，例如 www.example.com
GitHub 仓库：https://github.com/组织/官网仓库.git
源分支：master
发布分支：publish
模板目录：. 或 website-template
模板标识：standard-static-v1
```

创建站点后系统会返回一个专属 API Key。该 Key 只决定“文章进入哪个网站”，不决定页面样式；页面样式完全来自该网站仓库中的模板文件。

## 8. Cloudflare Pages

Cloudflare Pages 连接同一 GitHub 仓库并配置：

```text
生产分支：publish
构建命令：留空
输出目录：.
```

Worker 每次完成发布后提交 `publish` 分支，Cloudflare Pages 会自动部署。

## 9. 接入验收清单

- [ ] 官网仓库有独立的 `master` 与 `publish` 分支。
- [ ] `publisher.config.json` 路径与后台 `templateRoot` 一致。
- [ ] 首页和资讯列表页都有 `{{article_cards}}`。
- [ ] `templates/article.html` 已创建，并包含 `{{content_html}}`。
- [ ] 文章页的 CSS 已限制图片、视频和 iframe 最大宽度。
- [ ] 后台站点配置的仓库、分支、域名正确。
- [ ] 已保存该站点返回的专属 API Key。
- [ ] Cloudflare Pages 的生产分支设置为 `publish`。
- [ ] 使用一篇测试文章完成“保存 → Worker → GitHub → Cloudflare”端到端验证。
