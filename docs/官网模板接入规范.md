# 静态官网模板接入规范（v1.3.1）

模板通过后台ZIP上传或受限服务器目录导入，系统校验并冻结为独立版本。绑定网站后，Worker将模板与发布快照合成为完整静态归档，由客户Agent部署到Caddy。

## 1. 最小目录结构

ZIP可直接包含下列文件，也支持单层外包目录。目录导入时选择实际模板根目录。

```text
index.html
news/index.html
assets/site.css
templates/article.html
templates/article-card.html
publisher.config.json
```

`publisher.config.json`、文章详情与卡片模板都是必需项。`robots.txt`和`sitemap.xml`由构建器生成；无需手工维护。源模板中的固定页面和资源会一起打包，`templates/`和发布配置不进入客户网站。

## 2. 发布配置

```json
{
  "version": 1,
  "protocol": "standard-static-v1",
  "homePage": "index.html",
  "newsListPage": "news/index.html",
  "articleTemplate": "templates/article.html",
  "articleCardTemplate": "templates/article-card.html",
  "articleOutput": "news/{{slug}}/index.html",
  "assetsDirectory": "assets",
  "articleCardsPlaceholder": "{{article_cards}}"
}
```

以上路径相对于模板根目录，必须指向实际文件。当前首页必须输出为 `index.html`。`articleOutput`中的 `{{slug}}`实际替换为系统文章ID，不能与固定页面输出路径冲突。

## 3. 官网公共字段

所有输出HTML可使用：

```text
site_name, company_name, home_title, home_description,
contact_phone, contact_phone_url, site_domain, icp_number, icp_url
```

例如：

```html
<h1>{{home_title}}</h1>
<p>{{home_description}}</p>
<a href="{{contact_phone_url}}">{{contact_phone}}</a>
<footer><a href="{{icp_url}}">{{icp_number}}</a></footer>
```

`company_name`来自创建网站时的客户名称；后台官网编辑提供标题、介绍、电话和备案字段。硬编码文字不会自动变成可编辑字段。

需要电话与备案校验时，将配置改为：

```json
{
  "protocol": "standard-static-v1.1",
  "requiredCapabilities": ["contact-phone", "icp-fields"]
}
```

将这两个字段合并到完整配置中，不要覆盖其他必填字段。v1.1必须声明icp-fields。声明后相关HTML需要电话及备案占位符，备案号放在footer内，发布前电话和备案号必须有值；备案链接固定为 `https://beian.miit.gov.cn/`。旧v1模板可逐步升级。

## 4. 首页和资讯列表

首页与资讯列表均需包含配置指定的占位符：

```html
<div class="article-grid">{{article_cards}}</div>
```

构建器填入当前发布快照中所有标记为published的文章。文章保存后仍需发布网站才能更新线上。

## 5. 文章卡片模板

```html
<article>
  <time datetime="{{published_at_iso}}">{{published_at}}</time>
  <h3><a href="{{article_url}}">{{title}}</a></h3>
  <p>{{summary}}</p>
</article>
```

卡片字段：`article_id`、`article_url`、`title`、`summary`、`category_name`、`published_at`、`published_at_iso`、`cover_image_url`。当前分类固定为“生活资讯”，封面字段为空，尚无独立分类或封面管理。

## 6. 文章详情模板

详情模板必须包含 `{{content_html}}`，可加入：

```html
<main>
  <a href="{{home_url}}">首页</a>
  <a href="{{news_index_url}}">资讯</a>
  <h1>{{title}}</h1>
  <p>{{summary}}</p>
  <article class="article-content">{{content_html}}</article>
  <section>{{related_articles}}</section>
</main>
```

除公共字段和卡片字段外，详情页支持：`title_json`、`summary_json`、`content_html`、`updated_at_iso`、`seo_title`、`seo_description`、`seo_keywords`、`canonical_url`、`cover_image_block`、`tag_links`、`related_articles`、`home_url`、`news_index_url`、`asset_prefix`。

富文本正文经过清洗后插入；普通文本被转义。标题等普通文本字段由构建器转义，HTML片段不应二次转义。JSON字段用于JSON字符串上下文。当前cover_image_block、tag_links、seo_keywords为空。建议为 `.article-content img`设置 `max-width:100%;height:auto`。

## 7. 上传、绑定与验收

1. 上传ZIP并查看校验结果；默认压缩64MB、展开256MB、最多10000条目。
2. 拒绝目录穿越、隐藏路径、软链接、程序文件等不允许内容。仅上传符合规范的静态资源。
3. 绑定客户网站，保存官网资料，添加一篇测试文章并设为发布内容。
4. 管理员在「模板管理」生成草稿预览。预览不创建上线版本，禁用脚本和表单，有效30分钟。
5. 绑定客户服务器，发布并等待Agent部署成功。
6. 在正式域名检查首页、固定页面、资讯、电话、备案、图片、CSS/JS和HTTPS；动画与交互需在客户测试域名验证。

模板导入后按内容哈希固定。源目录后续修改不会改变已导入版本，需要重新导入、绑定并发布。构建会检查HTML中的本地资源链接与残留占位符，但不保证任意JS运行时请求都有效。
