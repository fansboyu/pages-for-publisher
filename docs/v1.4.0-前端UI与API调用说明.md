# 数告星发布中心 v1.4.0：前端UI与API调用说明

日期：2026-11-07。适用于前端开发、UI改造和接口联调。后端接口完整字段与任务状态见[后端参考](v1.4.0-后端架构与API参考.md)。

## 1. 前端结构

前端采用原生JavaScript、HTML、CSS，不使用React/Vue路由。public/app.js管理会话状态、当前页面view、selected网站、导航、业务页面渲染与事件绑定。各模块通过window导出的渲染/绑定函数接入。

| 文件 | 职责 |
| --- | --- |
| public/index.html | 样式与脚本加载顺序，挂载#app与#toast |
| public/app.js | 登录、角色菜单、网站切换、公共API函数和主渲染 |
| workspace-ui.js / workspace.css | 工作台卡片、横幅、指标、待办 |
| website-builder-ui.js / website-builder.css | AI建站对话、草稿编辑、预览与历史 |
| external-ui.js / external.css | 网站媒体目录、分行筛选、报价、投稿记录、外发分类导航 |
| geo-query-ui.js / geo-query.css | GEO模式、平台选择、报价、确认、图表、任务记录、单价配置 |
| billing-ui.js | 金额账户、预算、账单和管理操作 |
| provisioning-ui.js | SSH指纹、预检、确认安装与任务跟踪 |
| analytics-ui.js | 网站访问报表 |
| deployment-ui.js / templates-ui.js | 客户服务器和模板管理 |
| editor.js / editor.css | 编辑器集成 |
| style.css / classic.css | 基础布局与现有页面样式 |
| assets/workspace-*.webp | 工作台装饰素材，不承载业务数据 |

生产frontend容器内置静态资源及Jodit文件，通过同源反向代理访问API。开发API也能直接提供public静态资源。前端没有数据库、OSS或供应商密钥。

## 2. 页面与导航

工作空间包含工作台、网站管理、发布与版本。文章发布区为外部文章发布树，网站媒体和发布记录分别展示；B2B、自媒体大V、个人自媒体标记待接入且禁用。

AI内容工作台包含智能建站、文章内容、AI图文、视频规划、知识库、官网编辑、素材。数据与管理包含AI数据中心、访问统计、员工、余额与账单、客户以及管理员专属入口。

后端permissions.pages决定页面可见性。前端allowedPage只控制展示，不能代替后端siteFor和管理员权限校验。直营员工与代理商的实际可见范围依账号角色和归属确定。

主侧栏支持滚动与窄屏收起；移动端导航按钮控制展开。新增模块应维护收起态可点击性和显示名称，不能只在大屏截图中验证。

## 4. 请求和响应约定

同源fetch默认携带Cookie。api(path,body)对有body的请求使用POST，否则GET；JSON请求使用Content-Type:application/json。返回非2xx时读取error，401返回登录，其他错误通过toast或模块错误栏展示。

```javascript
const response = await fetch('/api/geo-query', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({
    action: 'quote', site: 'SITE_ID', mode: 'live',
    brand: '企业品牌', question: '目标问题', platforms: [1, 2, 4]
  })
});
const quote = await response.json();
if (!response.ok) throw new Error(quote.error);
// quote.amountCents是整数分；显示时除以100，不能把元再传回分字段。
```

返回结构并不统一包装成data：state直接返回状态对象，team返回数组，建站返回draft/jobs等，GEO返回settings/rows/stats等。不要假定所有接口都有data。

## 5. GEO页面详细交互

1. 选择网站及免费演示/正式模式；切换后记录与统计重新加载。
2. 填品牌词（最多100字）、问题（最多1000字），选择平台。正式平台由后端liveSupported控制。
3. 点击获取报价，保存quoteId、平台、单价、总价、请求编号；输入改变必须失效原报价。
4. 报价区域展示单价×平台数、总金额、2分钟有效期。真实提交使用明确费用确认。
5. 提交action=submit，confirmedAmountCents必须与报价一致；成功进入查询记录。
6. 待处理或待归档记录每10秒刷新；用户正在输入时避免刷新清空表单。
7. 截图归档失败显示重试按钮，仅执行retry-archive，不重新查询、不再次收费。
8. 管理员可设置0.20等金额、启用开关及开放平台。改价使旧正式报价失效。

图表根据platform ID关联计数，不按数组位置拼接结果。环形图为平台命中数/全部命中数；柱状图浅色为查询数、实色为命中数；零命中显示灰环。当前数据模式必须在页面提示中清楚说明。

公开截图链接允许HTTPS或本地/objects/media路径；数据库查询记录仍需要授权。不要把供应商临时截图地址直接当作持久归档地址。

## 6. 外发媒体页面详细交互

筛选类型field_1到field_9分别对应行业、门户、地区、入口、收录、链接、速度、特殊行业、高级选项。各行单选，多行组合；sort支持空、asc、desc。重置清空筛选与搜索。当前筛选作用于供应商当前页，UI必须保留该范围说明。

跨页渠道选择保存在网站级Map中，最多10个。发布前选择已有文章，报价冻结内容，提交使用quoteId及requestKey。重复点击应禁用按钮；网络异常后保留同一请求编号，避免双重下单。

正式媒体刊发与退款尚未付费联合验收；该状态应在交付与上线时说明，不展示虚假完成提示。

## 7. 建站页面详细交互

网站草稿revision与官网siteRevision是不同字段。任务提交携带基准revision和报价信息；服务端发现草稿或站点被其他操作修改会拒绝覆盖。对话内容、变化字段和历史版本由服务端保存。

预览查看草稿效果；应用把建站草稿纳入官网内容；正式发布再生成发布包。撤销恢复上一版为新草稿；线上回滚通过发布版本页面执行。

## 8. 状态与错误展示

| 状态/HTTP | 前端处理 |
| --- | --- |
| 202 | 已受理，不等于供应商成功或网站上线 |
| 400 | 字段错误，保留输入并提示 |
| 401 | 会话过期，重新登录 |
| 403 | 无权限，不通过隐藏按钮绕过 |
| 402 | 余额或预算不足，引导查看金额页面 |
| 409 | 版本、价格、重复请求冲突，刷新后重新报价 |
| 429 | 请求或并发受限，等待后再试 |
| 503 | 功能未启用或供应商配置缺失 |
| review | 结果不明待核查，不显示重发付费请求按钮 |
| archive failed | 查询已结束，允许单独重试截图归档 |

## 9. 前端扩展约定

新增页面需同步permissions.pages、tabs、navSections、page渲染和bind函数；新增JS/CSS需同步index.html与API publicFiles白名单，并重建frontend镜像。不要只改API容器而保留旧静态镜像。

切换网站、模式与页面时递增请求序号，防止旧响应覆盖新页面；新UI开发应继续沿用业务对象归属，不通过URL参数扩大客户范围。

任何来源的企业资料、文章、供应商备注与错误都需要文本转义。文章HTML使用已有safeHtml清理；不能将资料当成模型执行指令。

## 10. 本地运行与检查

npm run dev默认API在4418；npm run frontend:local构建独立静态容器并提供4419。本次开发可能使用4424端口，不应把临时端口当作生产固定配置。

检查命令：node --check public/app.js；npm run test:permissions；npm run test:frontend；npm run test:geo。UI截图不替代真实供应商验收。
