# 数告星发布中心 v1.3.6 功能说明

**版本：** v1.3.6  
**适用对象：** 直营管理员、代理商及其员工  
**代码版本：** GitHub `main` 当前包含 v1.3.6 后续菜单布局提交 `4482c92`。

## 1. 版本概览

v1.3.6 在 v1.3.5 的角色权限、员工账号和网站发布能力上，整理了网站管理界面，并纳入金额计费和服务器 SSH 自动接入两项本地增量。系统服务端仍由 API、Worker、PostgreSQL、Redis/BullMQ、Agent、Caddy 和独立 Provisioner 协作。

左侧导航按工作内容分为三组：

| 分组 | 菜单 |
|---|---|
| 网站运营 | 网站管理、访问统计、发布与版本 |
| 内容工作台 | 文章内容、AI 图文创作、AI 视频创作（规划）、企业知识库、素材中心、官网编辑 |
| 平台管理 | 客户与代理商、员工账号、模板管理、服务器与部署、服务器自动接入、GEO 接口、余额与账单 |

账号只能看到服务端授权的菜单；代理商与员工只访问所属代理商的数据。直营管理员拥有平台管理权限。

## 2. 网站管理与发布

- 网站管理页将网站列表、访问统计和发布版本作为页面切换入口。
- 快捷入口用于创建地区站、进入模板管理和服务器部署管理。
- 网站卡片突出“管理内容”和“发布新版本”；线上访问、控制台预览及地区站操作放在“更多”。
- 每个网站独立保存域名、内容、SEO、文章、发布包和版本记录。发布生成新静态版本，历史版本可回滚。
- 网站卡片和导航会按当前登录账号的可见范围筛选。

## 3. AI 图文与企业知识库

- DeepSeek 负责生成文章，阿里云百炼负责封面和正文配图；图片持久化到配置的本地存储或 OSS，再插入文章对应段落。
- AI 图文创作按配置报价并预占金额；生成成功后自动保存文章并进入发布流程，不需要逐篇人工审核。
- 企业知识库按客户保存企业事实、产品服务、服务流程、地区信息和行业词条，文章生成时作为参考。
- 同一客户的地区站共享企业知识库，但每个地区站可维护独立域名、地区词、文章和访问统计。

供应商密钥必须由服务端配置，不能放进前端。实际图片外网访问还取决于 OSS Bucket 权限、域名 HTTPS 和对象读权限配置。

## 4. 访问统计

系统可统计 PV、估算访客、趋势、热门页面、来源、设备和地区域名。可按网站配置统计域名；数据按代理商范围隔离。统计采集不保存原始 IP、完整 User-Agent 或 URL 查询参数。

## 5. 金额计费

- 按金额结算，不使用积分换算。
- 支持代理商余额、客户独立结算、管理员人工充值、图文价格配置、客户月预算和追加式账单流水。
- AI 生成前报价并冻结金额；成功后扣款，明确失败时按业务状态释放或退款。超时状态保留冻结，以便核对，避免重复调用造成重复扣费。
- 视频价格目前仅是预留字段；尚未接入真实视频生成、在线支付或供应商成本自动采集。

## 6. 服务器与 SSH 自动接入

- Provisioner 是独立容器，通过内部认证接口接收任务；不访问数据库、Redis、平台数据卷或 Docker socket。
- SSH 密码或私钥仅在执行器内存中短暂保存，不进入数据库或日志。接入前显示主机指纹并进行只读预检，安装前需要再次确认。
- 当前自动安装范围为无现有业务占用的 Ubuntu 22.04/24.04、x86_64、root/systemd 主机。若检测到已有网站服务、目录或所需端口冲突，会阻止安装。
- Agent 回连主控验证成功后，接入任务才标记完成；接入不会自动绑定网站或发布网站。
- 不支持将已有 Nginx Proxy Manager 或现有 Caddy 自动迁移到新接入方案。真实云主机和 systemd 环境需要单独验收。

## 7. 账号与角色

- 直营管理员可管理平台客户、代理商、员工、模板、服务器、GEO 接口和计费配置。
- 代理商只能查看自己名下客户和网站；代理商员工共享所属代理商的数据范围。
- 员工账号可创建、启用和停用；停用会拒绝新登录并撤销已有会话。
- 页面隐藏只是界面控制，实际数据权限仍由服务端校验。

## 8. 当前能力边界

- “AI 视频创作（规划）”仅为规划入口，不会提交真实视频生成任务或产生视频模型费用。
- 计费采用管理员人工充值，不含在线支付。
- SSH 自动接入的自动化测试使用模拟远端环境；不能替代对真实服务器、网络策略、systemd 和 Agent 回连的验收。
- 备份命令可打包 PostgreSQL 与平台文件；异地复制、密钥保管和隔离恢复演练仍需按部署环境配置。
- OSS 可用性取决于实际 Bucket、地域、RAM 权限、访问域名和 HTTPS 配置；自动化测试不会证明生产 OSS 公网访问正常。

## 9. 本地验证

项目要求 Node.js 24 或更新版本。常用命令：

```bash
npm run dev
npm test
npm run test:frontend
npm run test:permissions
npm run test:billing
npm run test:provisioning
```

AI、告警、多站点和阶段一回归可分别运行 `npm run test:ai`、`npm run test:alerts`、`npm run test:multi-site` 和 `npm run test:phase1`。Mock、演示数据和模拟远端测试不代表真实供应商、OSS 或云主机已通过线上验收。
