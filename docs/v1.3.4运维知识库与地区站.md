# v1.3.4 运维与内容能力

## 企业知识库

从左侧“企业知识库”选择企业所属站点，添加已核实且可以公开的企业资料。建议按“企业简介、产品与服务、服务流程、资质与标准、地区信息、行业词库”分类维护。每条内容包含分类、标题、事实说明和行业词。不要录入账号密码、客户个人信息、未公开合同或未经确认的承诺。

同一企业的所有地区站共享知识库。AI 文章生成会将知识库事实和行业词发送给文本模型，要求模型优先引用已确认信息并避免编造。真实 AI 模式会将这部分业务资料发送给配置的模型服务商，客户应按其数据管理要求配置供应商。

## 地区站

网站管理卡片中选择“地区站”，填写名称、地区、该地区的独立域名和地区重点词。系统沿用同一客户归属，复制来源站当前首页初始内容及模板版本；文章、发布历史和服务器绑定不复制。创建后分别编辑地区首页与 SEO 文章，再绑定部署服务器并发布。每站统计相互独立，知识库共享。

域名必须唯一。客户/运维仍需将地区域名解析到对应服务器，完成 HTTPS 证书和 Caddy 可访问性配置。地区站不会自动复制源站的 Agent 服务器绑定，因此需在“服务器与部署”中单独绑定。

## 备份

生产发布目录执行：

```powershell
npm run backup
```

确保 `docker compose -f compose.production.yml ps` 中 API 和 PostgreSQL 均运行。默认写入 `./backups`，生成带时间戳的 tar.gz、SHA-256 文件和内部清单。包内包括数据库 custom dump 和平台容器 `/data` 目录；不包含 `.env` 和 Redis 缓存。配置 `BACKUP_DIR`、`BACKUP_RETENTION_COUNT` 可调整输出目录与保留份数。恢复需在匹配版本的隔离环境中恢复数据库并解开 `platform-data.tar.gz` 至 API/Worker 共用的数据目录，检查对象存储归档、网站版本及媒体访问。

自动化备份命令当前由外部调度器运行，例如 Windows 任务计划程序或 Linux cron；生产部署应将备份复制到另一个故障域，并安排定期恢复演练。当前命令不自动上传 OSS，也不包含 `.env`，所以需独立保护部署密钥和配置。

## 告警

在 API 与 Worker 共同使用的 `.env` 设置 `ALERT_WEBHOOK_URL`，Worker 每分钟检查最近构建/部署失败和站点绑定 Agent 的离线状态，并发送通用 JSON：`source`、`title`、`text`、`occurredAt`。用自有 Webhook 接收端将 JSON 转换为钉钉/企业微信等目标格式。设置 `ALERT_COOLDOWN_MINUTES` 控制相同事件重复提醒的间隔。Agent 恢复心跳后离线告警自动解除。

未配置 Webhook 时，系统继续工作但不会发送外部提醒；Worker 日志会显示告警发送错误。生产验收应测试失败通知、离线通知、恢复后再次离线及接收端不可用时的日志。
