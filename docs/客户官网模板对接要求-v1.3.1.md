# 数告星发布中心：客户官网模板对接要求

适用发布中心版本：**v1.3.1**
推荐模板协议：**standard-static-v1.1**
文档日期：2026-10-18
交付对象：客户、官网设计制作方、前端开发人员。

> 本文可以直接作为模板制作与交付要求。已有官网应尽量保留原有视觉和布局，按本文接入配置、内容占位符及文章模板。
>
> 发布中心版本“v1.3.1”和模板协议“standard-static-v1.1”是两个不同概念，不要把配置中的protocol填写成v1.3.1。

## 一、交付目标与职责

客户交付一个**完整、可直接运行的静态官网ZIP**。发布中心负责替换官网资料、插入文章、生成静态页面并发布到客户服务器。

| 客户模板制作方负责 | 发布中心管理员负责 |
| --- | --- |
| 官网视觉、布局、响应式设计和静态交互 | 创建网站、填写客户名称及网站域名 |
| 首页、资讯列表、文章详情及固定页面 | 上传ZIP、检查模板校验结果、绑定模板 |
| 配置文件、占位符和完整CSS/JS/图片/字体 | 保存标题、介绍、电话、备案号和文章 |
| 资源路径正确，正文图片适配移动端 | 草稿预览、绑定服务器、发布及回滚 |

当前后台可编辑的是官网标题、介绍、电话、备案号，以及文章标题、摘要、正文和状态。客户名称来自网站归属信息。服务项目、团队介绍、轮播内容等其他固定页面内容需要在模板中维护，不能假设任意文字都会自动变为后台可编辑字段。

官网无需依赖Git仓库、发布分支或第三方页面托管。客户模板不需要包含数据库、服务端程序、Agent或任何平台密钥。

## 二、必须交付的目录结构

推荐目录：

```text
客户官网/
├── publisher.config.json          # 必须：发布协议配置
├── index.html                     # 必须：首页
├── news/
│   └── index.html                 # 必须：资讯列表页
├── templates/
│   ├── article.html               # 必须：文章详情页模板
│   ├── article-card.html          # 必须：单篇文章卡片模板
│   └── site.defaults.json         # 可选：初始资料参考
├── assets/
│   ├── site.css                   # 示例使用的样式文件
│   ├── site.js                    # 可选：官网静态交互
│   ├── images/                    # 按实际需要交付固定图片
│   └── fonts/                     # 按实际需要交付字体
├── about.html                     # 可选：关于我们
├── services.html                  # 可选：服务介绍
└── contact.html                   # 可选：联系我们
```

- 首页必须输出为`index.html`。建议直接采用上面的路径，减少改动和路径错误。
- `templates/article-card.html`是**必需文件**，不能省略。
- 可增加固定页面，但导航中引用的页面必须实际存在；未交付的页面不要留下链接。
- 固定资源需要随ZIP完整交付。不要引用开发电脑磁盘地址、localhost服务、临时下载地址。
- `robots.txt`和`sitemap.xml`会由发布中心重新生成；无需交付自定义版本。
- 发布时`templates/`和`publisher.config.json`不会进入客户网站；将网站运行所需的CSS、JS、图片放在`assets/`等公开目录中。

## 三、必填发布配置

将下面文件放在模板根目录。新交付模板建议直接使用此配置。

### `publisher.config.json`

```json
{
  "version": 1,
  "protocol": "standard-static-v1.1",
  "requiredCapabilities": ["contact-phone", "icp-fields"],
  "homePage": "index.html",
  "newsListPage": "news/index.html",
  "articleTemplate": "templates/article.html",
  "articleCardTemplate": "templates/article-card.html",
  "articleOutput": "news/{{slug}}/index.html",
  "assetsDirectory": "assets",
  "articleCardsPlaceholder": "{{article_cards}}"
}
```

| 字段 | 填写要求 |
| --- | --- |
| version | 使用数字1 |
| protocol | 推荐standard-static-v1.1，不能填写发布中心版本号 |
| requiredCapabilities | v1.1必须包含icp-fields；推荐同时声明contact-phone |
| homePage | 使用index.html |
| newsListPage | 指向实际存在的资讯列表文件 |
| articleTemplate | 指向实际存在的文章详情模板 |
| articleCardTemplate | 指向实际存在的文章卡片模板 |
| articleOutput | 必须含有`{{slug}}`，推荐保持示例路径 |
| assetsDirectory | 静态资源目录，推荐assets |
| articleCardsPlaceholder | 推荐使用`{{article_cards}}` |

所有配置路径都是相对于模板根目录的文件路径，使用正斜杠`/`。JSON不支持注释、尾逗号和单引号。

`{{slug}}`当前会被替换为系统文章ID，并非客户自己填写的英文标题。例如文章ID为p123，输出路径为`news/p123/index.html`。不能将固定页面放在可能与文章输出冲突的位置。

旧协议`standard-static-v1`仍兼容，但新客户建议采用v1.1。不要自行添加requiredCapabilities，未知能力会被拒绝。

## 四、官网内容字段与电话、备案要求

### 4.1 公共字段

下列公共字段可在最终输出的HTML页面及文章详情模板中使用：

| 占位符 | 对应内容 | 用法建议 |
| --- | --- | --- |
| `{{site_name}}` | 后台网站名称 | 网站标题、导航 |
| `{{company_name}}` | 网站所属客户名称 | 品牌名称、页脚 |
| `{{home_title}}` | 官网编辑中的首页主标题 | 首页主视觉标题 |
| `{{home_description}}` | 官网编辑中的首页介绍 | 首页简介、描述 |
| `{{contact_phone}}` | 联系电话文字 | 页面展示 |
| `{{contact_phone_url}}` | 含tel:前缀的电话链接 | 直接用作href，不要再加tel: |
| `{{site_domain}}` | 网站域名，不含https:// | 需要展示域名时使用 |
| `{{icp_number}}` | 后台填写的备案号 | 页脚展示 |
| `{{icp_url}}` | 固定备案查询链接 | 直接用作备案链接href |

原本写死的文字不会自动替换。需要由后台维护的内容必须改为对应占位符。

公共占位符用于输出HTML；不要放到独立CSS、JS或JSON文件中期待自动替换。不要在其他模板引擎或前端框架中使用容易与这些字段冲突的`{{变量}}`语法。

### 4.2 v1.1的硬性要求

首页、资讯列表、about/services/contact等所有固定HTML页面，以及文章详情模板，都必须包含以下四项：

```text
{{contact_phone}}
{{contact_phone_url}}
{{icp_number}}
{{icp_url}}
```

其中备案号必须放在`<footer>...</footer>`内。文章卡片模板不强制加入这些公共字段。

可以在每个页面复用以下页脚：

```html
<footer class="site-footer">
  <span>{{company_name}}</span>
  <a href="{{contact_phone_url}}">咨询电话：{{contact_phone}}</a>
  <a href="{{icp_url}}" target="_blank" rel="noopener noreferrer">
    {{icp_number}}
  </a>
</footer>
```

备案链接由发布中心固定为`https://beian.miit.gov.cn/`。发布前，管理员必须填写真实联系电话和备案号；模板校验时的示例数据不会替代客户资料。

## 五、首页与资讯列表

首页和配置指定的资讯列表页都必须包含文章卡片占位符：

```html
<div class="article-grid">{{article_cards}}</div>
```

发布中心会在两个页面中插入标记为“发布内容”的文章卡片。请不要把占位符放进注释、脚本字符串或HTML属性中，也不要写死客户文章地址。

当前构建器会插入该站点快照中的全部已发布文章，没有首页文章条数、分类筛选或分页配置。设计时需要考虑文章较多及零篇文章的布局。

## 六、文章卡片模板

卡片文件只包含**一张文章卡片的HTML片段**，不要包含完整html/head/body文档结构。

### `templates/article-card.html`

```html
<article class="article-card">
  <time datetime="{{published_at_iso}}">{{published_at}}</time>
  <h3><a href="{{article_url}}">{{title}}</a></h3>
  <p>{{summary}}</p>
  <a href="{{article_url}}">阅读文章</a>
</article>
```

卡片可用字段：

| 占位符 | 说明 |
| --- | --- |
| `{{article_id}}` | 系统文章ID |
| `{{article_url}}` | 由发布中心计算的相对详情页地址 |
| `{{title}}` | 文章标题 |
| `{{summary}}` | 文章摘要 |
| `{{published_at}}` | 日期文字，当前取文章更新时间的日期部分 |
| `{{published_at_iso}}` | ISO格式时间，当前为文章更新时间 |
| `{{category_name}}` | 当前固定为“生活资讯”，不是可管理分类 |
| `{{cover_image_url}}` | 当前为空，不要依赖此字段显示封面 |

卡片渲染目前不提供官网公共字段，品牌名称和电话应放在外层页面中。

## 七、文章详情模板与SEO

详情模板是完整HTML页面。正文必须使用`{{content_html}}`插入，并包在可控制排版的容器中。不要将正文占位符放入属性或JavaScript字符串。

### `templates/article.html`

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{{seo_title}}</title>
  <meta name="description" content="{{seo_description}}">
  <link rel="canonical" href="{{canonical_url}}">
  <link rel="stylesheet" href="{{asset_prefix}}site.css">
</head>
<body>
  <header class="site-header">
    <a href="{{home_url}}">{{company_name}}</a>
    <nav><a href="{{home_url}}">首页</a><a href="{{news_index_url}}">资讯</a></nav>
  </header>
  <main>
    <article>
      <h1>{{title}}</h1>
      <time datetime="{{published_at_iso}}">{{published_at}}</time>
      <p class="summary">{{summary}}</p>
      <div class="article-content">{{content_html}}</div>
    </article>
    <section>
      <h2>相关阅读</h2>
      <div class="article-grid">{{related_articles}}</div>
    </section>
  </main>
  <footer class="site-footer">
    <span>{{company_name}}</span>
    <a href="{{contact_phone_url}}">{{contact_phone}}</a>
    <a href="{{icp_url}}" target="_blank" rel="noopener noreferrer">{{icp_number}}</a>
  </footer>
</body>
</html>
```

详情页除公共字段和卡片字段外，还支持：

| 字段 | 当前行为 |
| --- | --- |
| content_html | 已清洗富文本，或经过转义和换行处理的普通文本 |
| seo_title | 文章标题＋客户名称 |
| seo_description | 文章摘要 |
| canonical_url | 根据客户域名和文章路径生成的完整HTTPS地址 |
| home_url / news_index_url | 当前文章页到首页、资讯列表的相对地址 |
| asset_prefix | 当前文章页到assetsDirectory的相对路径，已包含结尾斜杠 |
| related_articles | 其他文章中的最多3篇，使用同一卡片模板生成 |
| updated_at_iso | 文章更新时间 |
| title_json / summary_json | 已作JSON字符串内容转义的标题、摘要；仅用于相应JSON字符串上下文 |
| seo_keywords / cover_image_block / tag_links | 当前为空，不要依赖其生成SEO关键词、封面或标签 |

文章正文以安全HTML片段插入，不应再次转义。普通标题等文本由构建器转义。不要将普通HTML转义字段直接拼到JavaScript代码或JSON中。

## 八、样式与资源路径要求

### `assets/site.css`

```css

body { margin: 0; color: #24312d; background: #fff; font: 16px/1.7 system-ui, sans-serif; }
a { color: #176b50; overflow-wrap: anywhere; }

nav { display: flex; gap: 20px; flex-wrap: wrap; }
main { min-height: 60vh; padding-bottom: 40px; }
.hero { padding: 48px 0; }
h1 { font-size: clamp(28px, 5vw, 48px); line-height: 1.25; overflow-wrap: anywhere; }
.article-grid { display: grid; grid-template-columns: repeat(auto-fit, minmax(min(100%, 260px), 1fr)); gap: 20px; }

.article-content img, .article-content video, .article-content iframe { display: block; max-width: 100% !important; margin: 24px auto; }
.article-content img, .article-content video { height: auto !important; }
.article-content table { display: block; max-width: 100%; overflow-x: auto; }
.site-footer { padding: 24px 0; border-top: 1px solid #dce5df; display: flex; flex-wrap: wrap; gap: 20px; }
.summary { color: #53635b; }
```

这是用于验证接入的基础样式，不限制客户采用自己的配色、字体和布局。

路径要求：

1. 推荐使用相对路径，方便在草稿预览和正式域名下复用。
2. 首页资源示例：`assets/site.css`；资讯列表：`../assets/site.css`；文章详情：`{{asset_prefix}}site.css`。
3. `asset_prefix`已经带结尾`/`，后面不要重复加斜杠。
4. HTML、CSS中的相对路径以各自文件所在目录为起点，注意大小写一致。生产Linux环境区分大小写。
5. 模板内固定图片放入ZIP；运营上传图片使用发布中心返回的地址，不要硬编码平台测试域名或临时签名地址。
6. 不得引用`templates/`内文件作为正式网站资源，该目录不会公开发布。
7. 构建器检查HTML中的本地src/href链接，但CSS的url()、srcset、JS动态请求仍需制作方逐项验收。

## 九、静态交互与兼容性

- 支持交付编译后的HTML/CSS/JS及静态资源，正式客户网站可运行静态交互。
- React、Vue等工程如用于制作，交付的是构建后的静态产物，并额外满足本文文章模板与占位符协议；仅交付源码工程不能直接接入。
- 不支持在客户网站运行PHP、Node服务端、SSR、数据库或登录会员后端。需后端的表单、搜索等功能应事先单独约定。
- 采用动画时，建议默认可看到主体内容；不要必须等待JS移除遮罩或触发滚动后才显示全部内容。
- 草稿安全预览禁用JS、表单等能力，因此主要用于核对静态布局、资料和文章；动画、轮播及表单交互需要在客户测试域名验收。
- 富文本正文经过清洗，不应依赖在文章正文中注入script或任意交互组件。

## 十一、ZIP打包与交付限制

| 项目 | 默认要求 |
| --- | --- |
| 文件格式 | ZIP，非加密 |
| ZIP压缩体积 | 不超过64MB |
| 解压总体积 | 不超过256MB |
| 条目数量 | 不超过10000，目录条目也计数 |
| 包装层级 | 文件直接位于ZIP根目录，或只有一个外包文件夹 |
| 路径 | 使用正斜杠，不允许绝对路径、盘符、隐藏路径、上级目录 |

允许扩展名：

```text
.html .css .js .json .xml .txt
.webp .png .jpg .jpeg .gif .ico .svg
.woff .woff2 .ttf .webmanifest .pdf
```

不允许软链接、特殊文件、重复或仅大小写不同的路径、加密ZIP、脚本程序及未支持的扩展名。不要放入：

```text
.git/  .env  .DS_Store  __MACOSX/  node_modules/
package.json等源码工程文件和配置目录
.php  .exe  .sh  .ts  .tsx  .vue  .map  .avif  .otf  .md
数据库、服务器配置、Agent配置、证书、Token、AccessKey
```

部分工程文件即使扩展名属于允许列表，也不属于网站交付内容，应主动排除。交付说明、设计源稿和本MD请放在ZIP之外；上传器不接受README.md等Markdown文件。

推荐命名：`客户名称-官网模板-20261018.zip`。每次改版重新交付ZIP，发布中心按内容生成固定版本。修改原始文件不会改变已导入版本。

## 十二、常见错误与修正

| 提示或现象 | 检查和修正 |
| --- | --- |
| 根目录缺少publisher.config.json | 将配置放到根目录，去掉多层外包目录和额外同级文件 |
| 模板配置缺少某字段 | 对照完整JSON补齐，卡片模板不可省略 |
| 页面缺少文章占位符 | 首页和资讯列表都要包含配置指定占位符 |
| 某页面缺少电话/备案占位符 | 检查所有固定HTML及详情模板，复制完整公共页脚 |
| 备案号必须位于页脚 | 将icp_number放到footer标签内 |
| 静态页面或文章残留占位符 | 检查拼写、字段使用位置和是否使用了未支持字段 |
| 资源或页面不存在 | 检查路径、大小写、遗漏文件、未交付的导航链接 |
| 文章路径与固定页面冲突 | 固定页面避免占用news/<文章ID>/index.html结构 |
| 预览无动画或表单不可用 | 安全预览禁用JS和表单，到客户测试域名验证交互 |
| 保存文章后官网未变化 | 管理员还需发布网站，等待构建与Agent部署完成 |
| 上传成功但发布失败 | 核对电话、备案等必填资料，以及发布包限制和构建错误 |

上传限制与最终发布包限制是两套配置。默认发布包压缩128MB、展开512MB、最多20000文件；文章很多时，即使模板ZIP合规，完整网站也可能超限，应与平台管理员确认。

## 十三、交付与验收清单
