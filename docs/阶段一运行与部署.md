# 阶段一：总控、Agent、Caddy 与 OSS

> 此文保留阶段一 SQLite 版说明。当前默认已升级为 PostgreSQL 18.6 正式试点版，请优先阅读《正式试点版架构与运行.md》。Agent 0.3 另需 pilot/archive.mjs 与 tar-stream 依赖，包大小也已改为可配置。

## 已实现

- 兼容现有本地界面、Jodit 编辑器和 GEO Webhook。
- 总控注册服务器，一次性返回独立 Agent Token，数据库仅保存 Token 哈希。
- 管理员绑定网站与服务器，代理商不能注册服务器或跨代理商读取网站。
- 生成不可变发布包与内容快照，文件清单和整个发布包使用 SHA-256 校验。
- Agent 主动通过 HTTPS 轮询领取任务，无需客户服务器开放部署入口。
- 持久化任务队列、60 秒租约、15 秒续租、超时重新领取（最多 5 次），失败可手动重试。
- 同一服务器一次执行一个任务；按排队顺序执行发布和回滚。
- 本地/OSS 可切换存储。素材和编辑器共用接口，校验、限制尺寸并实际压缩为 WebP。
- OSS 模式中，Agent 使用 1 小时临时签名 URL 直接下载私有发布包；不携带总控 Token。
- Agent 验证路径、包与文件哈希，写入独立版本目录，通过 Caddy API 原子切换路由，验证首页，失败恢复旧配置。
- 客户 Agent 重连、未确认结果重报、总控重启后任务保留；Caddy独立运行。

本阶段保留 Node 24 + SQLite 的单机首版结构，没有重新实现大型多服务架构。部署 Agent 只依赖 Node 内置模块，可以单独复制到客户机器运行。

## 本地启动

1. 安装 Node.js 24，执行 `npm install`。
2. 将官方 Caddy 二进制放到 Windows 的 `tools/caddy.exe` 或 Linux 的 `tools/caddy`，也可设置 `CADDY_BIN`。
3. 先停止旧的 `npm start` 服务，执行 `npm run dev`。

本地启动器实际启动总控、独立 Caddy 和 Agent。自动注册本地测试服务器、绑定优佳家政，并生成第一份部署。

- 总控：http://127.0.0.1:4318
- Caddy 网站：http://127.0.0.1:4320/sites/s1/
- Caddy 管理 API：127.0.0.1:4321，只允许本机。
- 演示管理员：admin / Admin123!

登录后查看「服务器与部署」，可看到心跳、存储驱动、网站绑定和部署回执。文章、首页内容保存后点击发布；在版本列表选择历史成功版本回滚。

`storage/local-node/agent.json` 是本地 Agent 的私密配置，不可提交、公开或放到网站目录。`storage` 保留本地数据库、发布包、图片和测试记录。

## 本地验证

`npm run test:phase1` 会在随机端口和全新测试数据库中启动真实 Caddy、总控、Agent，不覆盖体验环境的数据。测试结束会停止这些临时进程，保留日志与报告。

覆盖：认证、代理商隔离、上传压缩、图文发布、Caddy 访问、回滚、Agent 停机补发、总控重启重连、破损包拒绝、失败重试、目录穿越拒绝、GEO 幂等。报告在 `storage/tests/<时间戳>/report.json`。

## OSS 配置

1. 在与 ECS 合适的内地地域创建两个不同的私有标准存储 Bucket：素材 Bucket、发布归档 Bucket。
2. 素材 Bucket 开启 CDN 私有回源，配置已备案的图片域名、HTTPS 与 DNS CNAME。保持 Bucket 禁止匿名访问。
3. 图片域名以 Bucket 根目录为源站，不额外改写路径。图片对象示例：`media/sites/s1/<内容哈希>.webp`。
4. 发布归档 Bucket 不开放公共读，不配置公开图片域名。对象在 `archives/sites/<站点>/<版本>.json.gz`。
5. 总控使用专用 RAM 身份，仅授权素材前缀写入、归档前缀读写。不要授予整个阿里云账号管理权限。CDN 使用独立私有回源授权。
6. 复制 `.env.example` 为 `.env`，填写真实地域、Bucket、RAM 凭据和 `MEDIA_PUBLIC_BASE_URL`，设置 `STORAGE_DRIVER=oss`。
7. 执行 `node --env-file=.env server.mjs`。如果需要本地三进程体验使用真实 OSS，执行 `node --env-file=.env scripts/local.mjs`。

静态 RAM AccessKey 与可选 STS Token 已支持。STS 临时凭据尚不自动刷新，到期前须更新环境并重启总控。后续可接 ECS RAM Role 凭据提供器。

本地模式的图片由总控 `/objects/media/` 提供，用于验证存储接口；只有真实 OSS+CDN 模式才能保证总控停机时图片仍正常访问。旧 `/media/` 链接继续兼容，本阶段不自动批量迁移历史图片。

禁止将 OSS 临时签名 URL 写进文章正文。素材返回的是稳定 CDN URL；临时签名仅用于 Agent 下载私有发布包。

## 客户 ECS 上安装

1. 安装 Node.js 24 和官方 Caddy，开放网站访问的 80/443 端口。部署 API 不需开放公网端口。
2. DNS 指向 ECS，确认实际内地资源与备案接入对应。
3. 使用专用 Caddy 实例，Agent 管理此实例的整份配置，不要与手工维护的无关网站混用。
4. 在总控注册服务器，保存一次性返回的配置，参照 `deploy/agent.example.json`。总控地址必须为 HTTPS。
5. 创建非 root 用户 `site-agent`，站点目录 `/var/lib/site-agent` 由该用户写入、caddy 组可读；Caddy证书数据目录单独持久化。
6. 将 `agent/agent.mjs` 放到 `/opt/site-control/agent/agent.mjs`，私密配置放到 `/etc/site-agent/agent.json`（限制读取权限）。
7. 参考 `deploy/site-agent.service` 注册 systemd 服务；实际 Node 路径不同需调整 ExecStart。
8. Caddy 管理端口固定 `127.0.0.1:2019`，由 Caddy服务启动并使用 `--resume` 恢复自动保存配置。
9. 在总控绑定网站，发布一次，再验证公网域名 HTTPS、文章和图片。

生产模式 Agent 增加 `127.0.0.1:4322` 的健康检查监听，只在本机访问。部署成功表示该监听下实际内容与版本响应头一致，公网 DNS、证书签发与续期仍需独立验收。

### 版本切换实现

每个版本写入独立不可变目录，Caddy 的 root 直接指向该目录。切换使用 Caddy `/load` 事务更新整份路由，成功后写入本地确认状态；失败恢复原路由。

这替代了 current 软链接，避免 Windows 与 Linux 软链接行为差异。`agent-state.json` 记录当前版本，`switch-journal.json` 记录中断前的切换意图；重启按已确认状态恢复。发布包中不包含 Token、内容快照或服务器配置。

## 本阶段边界

- 本地验证使用真实 Caddy，但使用本地目录模拟两个 OSS Bucket；未连接真实 OSS、ECS、DNS。
- 总控默认只监听本机，仍使用演示账号。正式公网部署前必须替换演示账户、配置反向代理 HTTPS、登录限速、数据库备份和运维监控。
- SQLite单进程持久化任务适用于首版试点，不支持多个总控进程同时写入；扩容时迁移 PostgreSQL 和独立任务队列。
- 发布包上限 32MB（压缩后）、文件总量上限 48MB、最多 3000 个文件；运营图片应走 OSS。
- 已归档快照与历史发布包不自动删除，需后续实现带引用检查的保留策略。
- 本阶段使用内置 basic-v1 模板；现有客户独立模板导入、可视化服务模块和模板版本管理后续接入。
