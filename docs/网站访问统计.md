# 网站访问统计

访问统计适用于 v1.3.3 起的发布中心。发布构建会自动把轻量统计脚本写入静态页面并随发布包部署。访客打开客户网站后，脚本向主控 API 上报页面路径、来源主机、设备类别和随机访客标识；后台按网站显示 PV、所选期间去重访客、每日趋势、热门页面、来源和访问域名。

## 客户侧需要填写什么

每个网站继续使用现有的「正式域名」字段作为主域名。访问统计不需要客户提供 API Key、埋点代码、OSS 参数或模型参数。

如果同一网站还通过多个二级域名提供服务，例如 `sh.example.com` 和 `hz.example.com`，在「访问统计」页面的「统计域名设置」中每行填写一个完整主机名。只填写域名，不带协议、端口或路径；主域名自动包含，最多可配置 50 个。

人工仍需完成：

1. 将每个主域名/地区域名的 DNS 解析到客户服务器。
2. 保存统计域名后，再发布一次网站，让客户服务器 Caddy 加载这些域名并签发/使用 HTTPS 证书。
3. 如果客户网站设置了严格 CSP，允许页面连接主控统计接口域名（`connect-src`）。统计脚本本身随站点静态文件提供，不需手工粘贴。

系统会拒绝把已经登记给其他网站的主机名重复绑定。每个客户账号只能查看其归属范围内网站的统计。不同客户的网站分别建立站点记录；需要合并展示时由相同企业下的站点分别查看，企业级汇总可后续扩展。

## 统计口径与隐私

- PV 每次页面打开都计一次；重复刷新也会增加 PV。
- UV 使用浏览器本地随机 ID 去重，并只在服务端存储不可逆哈希。它是估算值，清理浏览器数据、隐私插件拦截或更换设备都会影响准确性。
- 不保存原始 IP、完整 User-Agent、查询字符串或完整来源 URL；仅保存来源主机名和设备大类。
- 访客哈希记录保留 90 天；按页/域名的详细汇总保留 400 天；每日总量汇总长期保留。
- 基础机器人 User-Agent 会被过滤，但无法识别所有自动化流量；广告拦截器也可能阻止统计请求。
- 统计采集接口接受无后台登录的匿名事件，但会校验浏览器来源域名、限制请求大小和请求频率。域名校验不等于防止有意伪造流量。

## 部署与验证

默认统计地址由构建 Worker 的 `PUBLIC_BASE_URL` 自动生成：`<主控 HTTPS 域名>/api/public/analytics/collect`。只有主控 API 部署在不同公共地址时才需要设置可选变量 `ANALYTICS_COLLECT_URL`。生产前端已经把 `/api/*` 代理到 API 容器，不需要额外开放数据库或 Redis 端口，也不新增统计容器。

本地开发运行 `npm run dev` 后打开控制台的「访问统计」页面。新发布的网站访问页面后应出现数据；本地 Caddy 演示允许 localhost 来源。已有网站需要重新发布一次，使统计脚本随新版本上线。可运行 `npm test` 检查页面脚本、统计接口、域名校验、PV/UV 汇总和代理商权限隔离；测试只使用本地模拟访问，不代表客户公网 DNS、证书或真实流量已验收。
